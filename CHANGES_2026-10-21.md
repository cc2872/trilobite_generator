# Changes, 21 October 2026

## Tail controls (schema 6.4)

Four new parameters in the Tail group, fitted to the ranges TriloMorph's real pygidia span. Every default reproduces the
tail built since v4: for all ten presets and the default animal, the tail shell's vertices and the seven pygidial landmarks
are identical to `main` (checked by hashing the shell and comparing landmarks to 1e-9). `instrument.py`, `joints/`,
`tests/references` and the PREREG are untouched; the frozen readings cannot move.

| key | range | default | meaning |
|---|---|---|---|
| `tailOutlineExp` | 0.8–5.0 | 2.0 | superellipse exponent of the tail margin: 2 = the v4 half-ellipse, < 2 tapers to a pointed rear (1 = triangular), > 2 squarer |
| `pygAxisLen` | 0.25–0.97 | 0.85 | pygidial axis length / tail length (TriloMorph median 0.82, 5–95 % 0.27–0.93); the axis taper, rise, furrow and ring positions scale with it |
| `pygAxisFrac` | 0–0.6 | 0 | tail axis width / tail width; 0 = the thoracic `axisFrac`, as before |
| `pygBorderWidth` | −0.01–0.35 | −0.01 | tail border / tail half-width; negative = the head's `borderWidth`, as before |

* `anatomy/tail.py`: the margin, `xmax(y)` and the spine `outside()` test use the superellipse; the axis and border read
  the new keys; `plan()` also returns `axis_len`, `border_frac`, `outline_exp`.
* `landmarks.py`: `pygidium()` reads the axis end (LM2, axis curve) and the tail border (LM3, LM6, border curve) from the plan.
* `schema.py`: the four params, `CELLS` (b3 gets the axis length and width, a3 the outline and border), version 6.4.
* `web/index.html`: the four sliders in the Tail axis and Tail field + margin panels.
* Tests: `tests/test_tail_controls.py` (defaults equal v4, explicit values equal inherited ones, each control moves the
  tail, a pointed bordered tail builds as one watertight body); `test_schema.py` pins 6.4. Fast suite: all pass. The five
  slow full-build tests were not run; the vertex-identical tails at defaults cover them.

### What they buy (measured, and it is little)
Each of the 68 real TriloMorph pygidia was fitted (Powell, two starts) with the old tail controls and with old + new:

| | median distance | within 0.068 | within 0.11 | within 0.15 |
|---|---|---|---|---|
| nearest of 49,082 random animals | 0.137 | 12 % | 35 % | 62 % |
| fitted, old controls | 0.135 | 18 % | 38 % | 66 % |
| fitted, old + 6.4 controls | 0.132 | 21 % | 40 % | 69 % |

Eight tails improve by more than 0.01 (e.g. *Basidechenella* 0.036 → 0.018); most do not move. The worst fits are
phacopids and calymenids (*Acernaspis*, *Calymene*, *Erbenites*, *Paciphacops*, *Bollandia*, *Barrandeops*) and
*Kozlowskiaspis*. The mismatch these controls do not reach: in real pygidia the anterior margin sweeps back toward the
sides (the anterolateral corner LM7 lies behind the axis front LM1), while the generator's tail front is the straight
hinge line y = 0. A swept front is being tested in landmark space before any change to the hinge geometry.

### The swept front: tested in landmark space (not yet in the geometry)
Emulating it as one more fitted value (LM5–LM7 moved back by sweep × Lp × (x / wp)², sweep 0–0.8) and refitting:
on the first 36 of the 68 real pygidia the median distance falls to 0.035 (from 0.132), 97 % are within 0.068 and all
are within 0.11; *Calymene* goes from 0.27 to 0.06. The swept anterior margin is the missing tail feature. Building it
means the tail's front edge recedes behind the hinge toward the sides, so the last segment's rear edge must follow it:
a change at the joint, which needs a decision before it is made.
