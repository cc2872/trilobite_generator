## 1. Bug fix: the classic head's suture ran through the eye (anatomy/head.py, suture_path)
The loop round the eye was generated with the sine's sign reversed, so its points ran rear -> front. The path was
front margin -> the eye's REAR -> forward round the loop -> the eye's FRONT -> the margin: two straight grooves
through the eye. The comment on that line already described the intended order; the code now matches it.
Geometry changes only where sutureDepth > 0, which no preset or reference used before today.
New test: the path's y never decreases, on both heads, at six sutureEnd values.

## 2. The crescent head carries the facial suture and the eye ridge (anatomy/head_crescent.py)
* FACE gains suture_end, suture_depth, eye_ridge (all 0 = the approved head, bit for bit; _z == _z_base).
* suture_path(face), eye_ridge_path(face), _detail(x, y, face): the classic head's front branch and eye loop on the
  crescent's own outline, glabella and eye. The rear branch by sutureEnd:
    -1 .. -0.5  lateral margin, from the eye's rear level back to the widest line   (proparian)
    -0.5 .. 0   into the horn's root and down its centreline to the tip at 0        (gonatoparian: the horn is
                the genal spine, and the suture bisects it)
     0 .. +1    the notch, from beside the horn in to 0.6 of the notch's half-width (opisthoparian)
* plan(P) reads sutureEnd / sutureDepth / eyeRidge from P, hands the builder zfun_base + detail separately (so the
  builder's blur does not damp them, as on the classic head), and returns S["suture"], S["eye_ridge"].
  Depths are divided by the plan's scale, so the built groove is P's mm.
* isopod_model/body.face_of passes the three keys to the print head ONLY when a preset sets them, so every face
  without them keeps its key in source/cache. On the isopod model the preset's mm are scale-1 mm (its head is
  larger, the groove proportionally so).
Not changed: the generator's crescent plan still takes its glabella and eye from head_crescent's defaults, not from
P (only the isopod model's face_of maps them). Making plan() read the face from P is the next step for "both heads".

# 3 Oct 2026: the tail was being cut off on long-spined shaped heads (isopod_model/body.py)
The head-clearance loop subtracts the head from every part its spines reach, at every curl angle to 30 deg/joint.
A crescent's horns reach three segments. A harpetid prolongation or a trinucleid needle reaches the tail, and at
30 deg x 10 joints the tail has swung round to the head: the loop cut the tail down to a stump (harpes, cryptolithus,
ampyx; the "dropped flakes" in the earlier notes were this). For a shaped head each part is now cleared only while it
has turned less than CURL in total (k joints x a <= CURL). The crescent path is unchanged.
Result: harpes 226 x 390 x 52 mm (was 324 long), cryptolithus 206 x 329 x 57; tail 95.5 mm long on both; no flakes.
Correction to the earlier note: "harpes and cryptolithus clear to 24 deg/joint" was true only because the tail was
gone. With the tail whole: clear at 0 and 12 deg; at 24 deg harpes overlaps 155 mm3 and cryptolithus 58 mm3
(the tail reaching the head: where the curl stops; the exact angle is not measured).

## A way in for programs and AI agents (3 Oct 2026)

`web/agent.py` (new, registered in `web/app.py`): a program can make a trilobite on the pin model and get it measured with plain HTTP and JSON, no page and no JavaScript.

- `GET /llms.txt` (also `/agents.txt`) and `GET /api/agent`: the guide, as text and as JSON. The page's `<head>` points to it.
- `GET /api/agent/params` (`?group=`, `?q=`) and `GET /api/agent/preset/<name>`: the parameter table and each starting animal's values.
- `GET` or `POST /api/agent/make`: `preset=`, `chars=a,b`, any parameter `key=value`, `build=1` (adds one STL of the pin parts), `fill=`, `wait=`. Answers with the hash, what changed from the preset, the server's notes (clamps, settings that changed nothing), the reading, a one-sentence summary and links. A measurement takes about a minute and one runs at a time, so a slow one answers `running` and the same URL is asked again; the same animal is never measured twice. At most 6 wait at once.
- `GET /api/agent/animal/<hash>`: an animal already asked for.

It measures through the page's own path (`_measure` in `web/app.py`, split out of `/api/measure`), so the hash and reading are the page's, and each distinct animal goes to the recorder with `source: "agent"`. `web/index.html` takes `?joint=pin` so the answer's view link opens the measured model. `TRILO_AGENT=0` removes the routes; `TRILO_AGENT_TOKEN` puts a token on `make`. Tests: `tests/test_agent.py` (7, instrument stubbed).

Checked with a blind run: a fresh agent given only the address found the guide from the home page, made and measured two animals and downloaded an STL, using curl alone. Its 17 complaints about the instructions were folded back in (field glossary, preset values endpoint, warning that phacopida / ptychopariida / redlichiida do not measure on the pin, each answer echoing its own request, a readable stop sentence, POST example).
